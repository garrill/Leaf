# CLAUDE.md

Guidance for Claude Code when working in this repo.

## What this is

`Leaf`: native SwiftUI macOS git client, 4-column layout (repos (sidebar) → branches/history → changed files → diff). Currently in beta.

## Build, run, test

Plain Xcode project (`Leaf.xcodeproj`), scheme `Leaf`. No `Package.swift`, but it does resolve one SPM dependency (`Sparkle`) via Xcode's own package resolution.

```sh
xcodebuild -project Leaf.xcodeproj -scheme Leaf -configuration Debug build
xcodebuild -project Leaf.xcodeproj -scheme Leaf test
open /path/to/DerivedData/.../Build/Products/Debug/Leaf.app
```

- Quit any running instance before relaunching (`osascript -e 'tell application "Leaf" to quit'`) — xcodebuild won't overwrite a running bundle.
- Don't try to screenshot/screen-record the app (no permission in this terminal) — build, launch, let the user verify visually.
- `LeafUITests` need `-uiTestReset` (handled in `AppDelegate.resetStateIfRequestedForUITesting()`) to wipe `UserDefaults` first so each test starts from a repo-less sidebar.
- App Sandbox is disabled (`ENABLE_APP_SANDBOX = NO`) deliberately — app shells out inside arbitrary repo folders on disk.
- `.swift` files under `Leaf/` are picked up automatically (file-system-synchronized groups) — never need adding to `project.pbxproj`.

## Architecture gotchas

- **Git backend shells out to `/usr/bin/git`**, not libgit2/SwiftGit2 (no SPM package reliably links for macOS arm64).
- **AppState is the single source of truth.** `selectSource`/`selectFile` are assignment-only; the actual changed-files/diff git work happens in `AppState.loadChangedFilesForCurrentSelection`/`loadDiffForCurrentSelection`, triggered by `ChangedFilesView`/`DiffView`'s own `.task(id:)`, debounced ~180ms. Callers needing to see their own change immediately (`discardChanges`/`ignoreFiles`/`markResolved`) pass `immediate: true` to skip the debounce.
- **Liquid Glass column header blur** requires `.safeAreaBar(edge: .top)` (not `.safeAreaInset`) paired with `.scrollEdgeEffectStyle(.soft, for: .top)`, and only works over a real SwiftUI `ScrollView`/`List` — never over an `NSScrollView` wrapped in `NSViewRepresentable`. The bar also needs genuine non-empty content.
- **The window is entirely AppKit-owned, not a SwiftUI `WindowGroup`.** `LeafApp.swift` declares only a `Settings` scene; `AppDelegate` builds `MainWindowController`/`NSWindow` directly, hosting `MainSplitViewController`. Needed for `NSTrackingSeparatorToolbarItem` (pinning a toolbar item to an interior column divider — `NavigationSplitView` can't do this). `window.setContentSize(...)`/`.center()` must be re-applied *after* both `contentViewController` and `toolbar` are assigned, or AppKit collapses the window before dividers are positioned.
- **Column layout is `MainSplitViewController: NSSplitViewController`**, four `NSSplitViewItem`s each hosting SwiftUI via its own `NSHostingController` with `sizingOptions = []`. Divider positions are pinned via `splitView.setPosition(_:ofDividerAt:)` in `viewDidAppear()` (not derivable from `minimumThickness` or a hosting controller's frame). **Cross-column arrow-key focus navigation is not wired up** — each column has its own `NSHostingController`, so there's no shared `@FocusState` (see "Not yet implemented").
- **Per-column toolbar items are done via AppKit**: `MainToolbarDelegate` pins the branch-selector menu to the branches|files divider with `NSTrackingSeparatorToolbarItem`. A toolbar-hosted SwiftUI view must keep the *default* `NSHostingView` sizing (no `sizingOptions = []`) and avoid `.fixedSize()`, or it pops out of the tracking region far earlier than necessary. (A pure-SwiftUI per-column toolbar was tried and abandoned first — SwiftUI's own toolbar placements can't pin to an interior column.)
- **Diff pane is a real `NSTextView`** (`DiffCodeTextView.swift`), built on legacy TextKit 1 explicitly (`makeLegacyTextKit1()`) — the default initializer can come back TextKit 2-backed with no `.layoutManager`. Gutter is a separate `NSView` so line numbers never end up in a selection/copy. Word diff (`DiffCodeScrollView.diffRanges`) is token-level Myers via stdlib `difference(from:)` — never splits a word — and deliberately returns nil (whole-line replacement, no inner highlight) when <50% of non-whitespace chars are shared, so coincidental `.help(`/`")` matches between unrelated lines aren't highlighted. Strong word highlights only apply to a clean one-for-one block (equal removed/added line counts, every pair similar) — a lump of rewritten code keeps just the pale line backgrounds, even if one line in it happens to be similar.
- **Syntax highlighting** (`SyntaxHighlighter`) runs the bundled `Leaf/Resources/HighlightJS/highlight.min.js` in its own `JSContext` (an actor, off-main) and parses hljs's `<span class=…>` HTML by hand (`HighlightHTMLParser`) into compact per-line `SyntaxToken`s (UTF-16 offset/length/`SyntaxRole`). Never go back to `NSAttributedString(data:…documentType: .html)` (what HighlightSwift did): it loads WebKit in-process (~25 MB, permanent) and each run carries a ~1 KB attribute dictionary. Roles resolve with CSS precedence against `DiffSyntaxColors.selectorRoles`; colors are applied per theme at text-build time, so the token cache (`BoundedCache`, ~4 MB) is theme-independent. The JS context unloads after 2 min idle. Results are tagged to the diff text they were computed for, so stale highlights can't paint over a newly-selected file. Skipped above ~2000 lines (`DiffView.maxHighlightedLineCount`).
- **Every long-lived cache is cost-bounded** (`BoundedCache` LRU): `AppState.diffTextCache` (~16 MB of text), `changedFilesCache` (~50k entries), the syntax token cache. `AppDelegate` purges them all (and the JS context) on a `DispatchSource` memory-pressure event via `AppState.purgeCaches()`.
- **`BranchListView`'s `List(selection:)` binding must ignore `nil` in its setter** — macOS fires a spurious `nil` deselect before every real click.
- **Git quotes ambiguous pathnames** (spaces, quotes, non-ASCII) as C-style escaped strings in porcelain output — always parse through `GitRepository.unquoteGitPath(_:)` or later `checkout`/`clean`/`add` calls silently no-op.
- **A caller-sized path list can't go on git's command line** — a commit/discard/stash over tens of thousands of files overflows the kernel argv/env limit, and `Process.run()` reports that as an *uncaught* `NSInvalidArgumentException` that `abort()`s the app (not a Swift throw). `GitRepository.runPathspec(_:paths:)` feeds the list to git on **stdin** via `--pathspec-from-file=- --pathspec-file-nul` (each entry `:(literal)`-prefixed to match the old trailing-`--` semantics); `runRaw`'s `input:` param does the stdin plumbing on its own thread. Byte-budget batching onto the command line was tried first and still overflowed ~12k paths.
- **Sidebar (`SidebarViewController`) is a real `NSOutlineView`**, not SwiftUI `List` — needed for native drag-reorder (a pure-SwiftUI `.draggable`/`.dropDestination` attempt had dead zones between rows). Don't set `outlineTableColumn` (reserves disclosure space on every row regardless of indentation). `NSHostingView` reuse identifiers must be unique per item id, or AppKit's view-reuse hands a row stale `@State`. Gate a row's `.onTapGesture` structurally (e.g. `if` inside `.overlay`) so it doesn't swallow clicks meant for a child `TextField`.
- **Every repo in `SidebarStore.repos` must be shown in the sidebar exactly once** (in an existing folder, or with one `.repo` entry in `topLevelOrder`). `SidebarStore.Snapshot.normalized()` enforces this on load (repairing and re-saving old data) and in `persist()`, which every mutation ends with — so a bug in one mutation can't leave a repo the app knows about but the outline never draws. Lost repos/folders are appended to the end of the top level.
- **Progressive titlebar/traffic-light scroll blur** (`NSSplitViewItemAccessoryViewController.preferredScrollEdgeEffectStyle`, macOS 26.1) only engages for a scroll view that's a direct AppKit descendant of its own split item's view controller (why the sidebar isn't SwiftUI-hosted). Also needs: the outline view's `.sourceList` background left alone, `wantsLayer = true` on both the sidebar root view and the split view, a real vertical `NSScroller`, and a top `NSSplitViewItemAccessoryViewController` with `preferredScrollEdgeEffectStyle = .soft`. Missing any one silently no-ops.
- **SwiftUI `.onKeyPress` fires based on `@FocusState` matching, not which nested AppKit responder actually has key focus** — check `NSApp.keyWindow?.firstResponder is NSTextView` and return `.ignored` where relevant, so editing a hosted rename field doesn't hijack the keystroke.
- **`truncationTooltip` instantiates nothing at rest.** Hover is SwiftUI `.onHover` (a plain modifier — unlike a permanent per-row `NSViewRepresentable` or `.contextMenu`, it does *not* force a macOS `List` to build every row up front; a lazy list only realises the on-screen ones). Only *while* the pointer is over the text does a transient `TooltipAnchor` `NSViewRepresentable` exist — it overlays the text exactly, so its `bounds` is the available width and `convert(_:to:nil)` is the text's screen position. It measures truncation once (Core Text, no view), and after the hover delay shows the full string in the shared `TooltipPanel` `NSPanel` positioned over the start of the truncated text. `isTopmostAtCurrentMouseLocation()` (a one-shot hit-test) suppresses it for a row scrolled under the `.safeAreaBar` header/footer. Because the check needs the render font and there's no SwiftUI→`NSFont` bridge, non-body callers pass an explicit `font:` (`.headline`/`.subheadline` sites).
- **Column 3's file `List` lives in `ChangedFilesList`, split from `ChangedFilesView`** — the list's `selection:` binding reads `appState.selectedFilePaths`, so keeping it in the parent made every file click re-run the parent `body` (four `.alert`s, overlays, load `.task`). The split confines a selection change to the small list subview. `header`/`mergeBanner`/footers and the row/context-menu helpers moved with it; `@FocusState` for the list and the commit field stay in `ChangedFilesView` and pass down as `FocusState<Bool>.Binding`.
- **`GitRepository.filesChanged(in:)`/`(inStash:)` pass `-M -l<renameDetectionLimit>`** (currently 400) so git's inexact rename detection can't run away on a huge commit — exact renames still detected, an inexact one past the limit shows as delete+add. Stays on `git show` (not `diff-tree` plumbing) so merge commits keep their default combined `--cc` file list. `DiffView` also refuses to render a diff over `maxInlineRenderLineCount` (20k) parsed lines even when the 5 MB blob-size cap passed.
- **Never display git's raw error text** — `--progress` commands report a failure after hundreds of meter lines, and an alert can't scroll. `GitErrorReport(rawOutput:)` gives a short `summary` and a complete, credential-stripped `fullLog`; show them with `GitErrorAlert`/`GitErrorMessageView`/`CopyLogButton`. `GitError` itself stays raw because callers pattern-match on it. `GitErrorAlert` is an `NSAlert` because every SwiftUI `.alert` button dismisses it, which would lose the message on copy. Caller-sized lists in alerts go through `AlertList.text`.
- **Merge** (`GitRepository.merge(branch:)`) uses `runRaw`, not the throwing `run` — a conflicting merge exits 1 by git's own design, indistinguishable by exit code alone from a genuine error. The reliable discriminator is `.git/MERGE_HEAD` presence (`isMergeInProgress()`).
- **A conflict isn't "resolved" just because the file was hand-edited** — `git status` keeps reporting a path as unmerged (`UU`) until it's staged; `GitRepository.markResolved(_:)` does the `git add`.
- **`FileChangeStatus.conflicted` needs the full two-letter porcelain code** (`UU`/`AA`/`DD`/`AU`/`UA`/`DU`/`UD`) checked before the single-char fallback — some conflict codes contain no `U` at all.
- **`completeMerge()`'s `git commit` must pass `--cleanup=strip` explicitly** — plain `-m` defaults to `--cleanup=whitespace`, which doesn't strip the `# Conflicts:` comment lines from `MERGE_MSG`.
- **A conflicted file's raw contents (with `<<<<<<<`/`=======`/`>>>>>>>` markers) aren't unified-diff output** — `DiffView.parse(_:)` requires `@@` hunk headers and silently drops everything else; `DiffView.parsePlainText(_:)` is used instead when `selectedFile?.status == .conflicted`.
- **Stash is single-slot in the UI** — `AppState`/`BranchListView`/`ChangedFilesView` only ever surface `stash@{0}`, no picking which stash entry to view/apply.
- **Sparkle auto-update**: `UpdaterHolder` holds the single `SPUStandardUpdaterController`, touched once at launch by `AppDelegate`; `LeafApp`'s "Check for Updates…" command reaches the same instance through that holder (SwiftUI `.commands` are declared independently of `AppDelegate`/`AppState`). `SUFeedURL` points at `appcast.xml` at the repo root.
- **Custom Info.plist keys need `INFOPLIST_FILE`, not `INFOPLIST_KEY_*`** — `INFOPLIST_KEY_<Key>` only synthesizes keys from Xcode's fixed known-key list, which Sparkle's keys aren't on. `Leaf/Info.plist` is merged in via `INFOPLIST_FILE` alongside `GENERATE_INFOPLIST_FILE = YES`, and excluded from Copy Bundle Resources via a `PBXFileSystemSynchronizedBuildFileExceptionSet` (otherwise it also gets copied in verbatim alongside the merged one).
- **Release**: `scripts/make_dmg.sh` builds Release, re-signs the app + Sparkle's nested helpers with the Developer ID Application identity, notarizes (`notarytool submit --wait`) and staples, then packages the DMG. Confirmed working end-to-end (v0.4.0 released via GitHub Releases, Sparkle successfully auto-updated in-app). `.github/workflows/ci.yml` (`workflow_dispatch` only) runs build+test on `macos-latest` with signing disabled; not yet confirmed green on a real push.
- **Diff hunks have no header row** — `HunkSeparatorOverlayView`/gutter borders mark hunk boundaries instead of `@@ ... @@` text.
- **Command palette (⌘K)** is a borderless `CommandPalettePanel: NSPanel` added as a child window of the main window, hosting SwiftUI `CommandPaletteView` (`Leaf/Views/CommandPalette/`). ⌘1–⌘9 are caught in the panel's `performKeyEquivalent` (the key window sees key equivalents before the main menu); ↑/↓/Return/Tab/Esc come through an AppKit `NSTextField` delegate's `control(_:textView:doCommandBy:)` (`PaletteTextField`), not `.onKeyPress`. Items are built once on open from in-memory `AppState` only (no git calls) and filtered synchronously per keystroke (`PaletteMatcher`, capped at 9). Commands run *after* the panel is dismissed (next run-loop turn) so alerts/sheets/open panels attach to the main window. Repo rows read branch/last-commit date from `RepoStatusStore` (`SidebarSyncStatus.currentBranch`/`lastCommitDate`); empty-query suggestions come from `RecentReposStore`, a separate MRU list so repo switches never mutate `sidebarStore.repos`. The panel is the card plus a transparent `CommandPaletteView.shadowInset` margin on every side with `hasShadow = false` — the card draws its own SwiftUI shadow into that margin (a card filling the panel edge-to-edge clips its shadow), and the panel's `sendEvent` treats clicks in the margin as clicking outside. The autofill ghost is drawn by the field's own custom field editor (`GhostFieldEditor`, TextKit 1, vended via `GhostTextFieldCell.fieldEditor(for:)`) from its layout manager's baseline — an overlaid label, even a frame-identical `NSTextField` twin, sat ~1pt low because the field editor and a static cell lay text out slightly differently. Unavailable commands stay listed with `unavailableReason` (ranked down by `PaletteMatcher.unavailablePenalty`, never the default selection) rather than hidden. Typed-argument rows ("New Branch foo", "Commit msg", a pasted clone URL/folder path) come from a per-keystroke `dynamicItems` closure and always lead. ⌥↩/⇧↩ arrive via `doCommandBy` (`insertNewlineIgnoringFieldEditor:` / `insertNewline:` + event flags); ⌘↩ is a key equivalent, caught in the panel like ⌘1–9. Command habits rank via `CommandUsageStore` (frecency, keyed by `PaletteItem.usageKey`). Jumping to a commit/file bumps `AppState.revealSelectionRequest` so `BranchListView`/`ChangedFilesList` scroll it into view (programmatic `List` selection doesn't). `AppState.originRemoteURL` comes from `GitRepository.originRemoteURL()`, which strips credentials (`redactedRemoteURL`) — never show or copy a raw `git remote get-url` result. GitHub URL parsing lives only in `GitRepository.githubPathComponents(fromRemoteURL:)`; owner and web URL both derive from it.
- **Commit message completion** (`Leaf/Views/CommitCompletion/`): triggers are `` ` `` (changed files, then diff symbols, then branches), `@` (people), `Co-authored-by:` (description only), `#` (issues/PRs), `:xx` (emoji) and a lowercase word at the start of the summary (conventional types). `CompletionTrigger.detect` is pure. The popup is a `.nonactivatingPanel` child `NSPanel` with `canBecomeKey = false` (and a first-mouse `NSHostingView`), so the commit `NSTextView` stays first responder. Its keys are routed in `CommitTextField.Coordinator.textView(_:doCommandBy:)` *before* the Return-commits/Tab-switches cases. An accepted or Esc'd token is suppressed until the caret leaves it, otherwise `@login` would immediately reopen. A file shows its bare name unless another changed file shares it (`FileCompletionNames`). Matching reuses `PaletteMatcher` through the shared `MatchKey`. Slow sources live in `CompletionDataStore` (off-main, per repo, `generation`-stamped): GitHub reads go through `gh api` when gh is installed and logged in (looked up at Homebrew paths, since a GUI app's PATH lacks them), otherwise unauthenticated api.github.com (public repos only). Failures are silent. Logins come from noreply emails or the commits API (persisted email→login map). `Leaf/Resources/emoji.json` is generated from github/gemoji.
